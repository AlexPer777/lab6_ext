# Лабораторная работа №6 — Программирование

Клиент-серверное приложение для управления коллекцией объектов `HumanBeing`. Продолжение [лабораторной работы №5](https://github.com/AlexPer777/lab_5): клиент принимает команды, а сервер выполняет их и хранит коллекцию.

**Курс:** 2-й семестр, весна.  
**Протокол:** TCP (Transmission Control Protocol).  
**Вариант:** номер не указан в предоставленном условии.

## Возможности

- Интерактивный клиент и отдельное серверное приложение.
- Передача типизированных объектов запросов и ответов с помощью сериализации Java.
- Работа клиента через неблокирующий `SocketChannel`.
- Повторные попытки подключения при временной недоступности сервера.
- Обработка коллекции через Stream API и лямбда-выражения.
- Сортировка передаваемых клиенту элементов по имени.
- Загрузка и сохранение серверной коллекции в JSON.
- Логирование работы сервера с помощью Log4j 2.

## Требования задания

Разделить программу из ЛР №5 на клиентский и серверный модули. Команды и аргументы должны передаваться объектами классов, а не простыми строками.

| Сервер | Клиент |
| --- | --- |
| Работает с файлом и управляет коллекцией | Читает команды из консоли и проверяет ввод |
| Назначает автоматически генерируемые поля | Сериализует команду и её аргументы |
| Принимает подключения, читает запросы, выполняет команды и отправляет ответы | Передаёт запросы серверу и выводит ответы |
| Сохраняет коллекцию при завершении и по серверной команде `save` | Не предоставляет команду `save`; `exit` завершает клиент |

По условию сервер работает в одном потоке и использует потоки ввода-вывода для сетевого обмена. Клиент использует неблокирующий сетевой канал. Обработка объектов должна использовать Stream API; передаваемая клиенту коллекция должна быть отсортирована по имени. Дополнительное задание — логирование этапов работы сервера через Log4j 2.

## Архитектура и структура

| Путь | Назначение |
| --- | --- |
| [lab/pom.xml](lab/pom.xml) | Родительский Maven-проект |
| `lab/lab-client` | Консольный клиент, разбор команд, проверка ввода и сетевой обмен |
| `lab/lab-common` | Модель, сериализуемые запросы и ответы, общие утилиты |
| `lab/lab-server` | Приём подключений, чтение запросов, выполнение команд и отправка ответов |
| [lab/collection.json](lab/collection.json) | Пример серверной коллекции |
| `lab/script*.txt` | Примеры скриптов |

Основные серверные классы: `ConnectionAcceptor`, `ServerRequestReader`, `ClientRequestHandler`, `ServerResponseSender`. Точки входа — `aleksei.lab.client.Client` и `aleksei.lab.server.Server`.

В текущей реализации сервер тоже использует `SocketChannel` для сетевого чтения и записи; объектные потоки применяются при сериализации в памяти. Это отличается от требования сетевого обмена через потоки ввода-вывода на сервере.

## Модель данных

В коллекции хранятся `HumanBeing` с координатами, датой создания, признаками героя и наличия зубочистки, скоростью удара, оружием, настроением и автомобилем. Модель продолжает ЛР №5.

В этой реализации идентификаторы имеют тип **UUID**. Для `update` и `remove_by_id` копируйте полный идентификатор из результата `show`. JSON-файл и идентификаторы из ЛР №5 с числовыми `id` нельзя считать совместимыми с этой версией.

Естественный порядок объектов задаёт `Comparable`; передаваемые клиенту списки сортируются по `name`.

## Команды

| Команда клиента | Действие |
| --- | --- |
| `help` | Справка |
| `info` | Информация о коллекции |
| `show` | Все элементы, отсортированные по имени |
| `add {element}` | Добавить объект |
| `update id {element}` | Обновить объект по UUID |
| `remove_by_id id` | Удалить объект по UUID |
| `remove_at index` | Удалить элемент по индексу, начиная с 0 |
| `clear` | Очистить коллекцию |
| `remove_greater {element}` | Удалить элементы, превышающие заданный |
| `sort` | Отсортировать коллекцию в естественном порядке |
| `count_greater_than_car car` | Посчитать элементы с автомобилем, превышающим заданный |
| `filter_contains_name name` | Фильтрация по подстроке имени |
| `filter_starts_with_name name` | Фильтрация по началу имени |
| `execute_script file_name` | Выполнить скрипт на сервере |
| `exit` | Завершить клиент |

Для интерактивного ввода объекта выполните `add`, `remove_greater` либо `update id` без записи полей в одной строке. Для автомобиля можно выполнить `count_greater_than_car` и следовать приглашениям.

Команда `save` вводится **в консоли сервера**. При выполнении `execute_script` файл должен быть доступен серверу; относительный путь отсчитывается от его рабочего каталога.

## Технологии

**Java 21**, **Maven**, **TCP**, **Java NIO**, **Java Serialization**, **Stream API**, **Gson**, **Log4j 2**.

## Сборка и запуск

Нужны JDK 21 и Maven 3. Сборка запускается из каталога `lab`, содержащего родительский `pom.xml`.

```bash
git clone https://github.com/AlexPer777/lab6_ext.git lab6_java
cd lab6_java/lab
mvn clean package
```

Запустите сервер:

```bash
java -jar lab-server/target/lab-server-1.0-SNAPSHOT-jar-with-dependencies.jar collection.json 9876
```

В другом терминале, из того же каталога `lab`, запустите клиент:

```bash
java -jar lab-client/target/lab-client-1.0-SNAPSHOT-jar-with-dependencies.jar 127.0.0.1 9876
```

| Приложение | Аргументы | Значения по умолчанию |
| --- | --- | --- |
| Сервер | `<collection-file> [port]` | Файл обязателен, порт `9876` |
| Клиент | `[host] [port]` | `127.0.0.1`, `9876` |

Для удалённого сервера замените `127.0.0.1` его адресом. Клиент выполняет до пяти попыток отправки запроса при ошибках соединения. Завершение клиента не останавливает сервер.

В IntelliJ IDEA откройте `lab/pom.xml` как Maven-проект и выберите JDK 21. Имена модулей `lab-client`, `lab-common`, `lab-server` соответствуют каталогам и Maven-зависимостям.
